## Security & credential handling

- **Never commit secrets.** Read credentials from env vars only; halt with a clear error if missing; never log them.
- Always `.gitignore`: `.env`, `.env.local`, `credentials.json`, `secrets/`, `node_modules/`, `__pycache__/`, `dist/`, `*.pyc`.
- Before committing: `git diff --cached | grep -iE "apikey|password|token|secret"`.
- **Respect privacy choices.** Don't proxy tracking SDKs through your own domain to dodge blockers.
- **Anything a redaction step must strip has to live where that step can reach it.** A page rendered "with all personal detail removed" strips fields from its data file at render time. A name hardcoded in the JS or the HTML shell is therefore unstrippable by construction, and ships in the very view that promises it doesn't. Same shape as a secret baked into a binary: the removal mechanism only covers the layer it runs on. Keep the sensitive class **exclusively** in the processed data, then add the test that greps the *code and markup* for that class and fails on a hit. That test caught a code comment naming the owner, written by the same session that wrote the rule.
- **The artifact's *name* is part of what you publish, and content-level redaction never covers it.** Repo names, URL slugs, deploy project names, branch names, and file names leak metadata that spotless contents cannot fix — and they're often visible exactly where the contents aren't, e.g. a public profile listing. A private-by-content set of pitch sites was still fully compromised by the plan to name their repos after the target companies, because the sites themselves link back to that profile. **Before publishing anything derived from sensitive work, read the identifiers out loud as if you were the last person who should see them.** Enforce it: fail the push if a remote URL matches the sensitive vocabulary.
- **A doc that mislabels its repo is a safety hazard, not just stale.** A README copied from another project described a repo holding nine competitors' pitches and personal career data as "a personal collection of coding best practices," with every link broken. It is the first thing a human or agent reads before deciding whether `--public` is safe, and it said yes. When a repo's risk isn't obvious from its contents, the README's first line is a control: state what's inside and what must never leave.
- **Check the security advisory index before risky supply-chain actions, targeted, not on every command.** Supply-chain attacks hit popular packages within hours of a maintainer phish. Fetch the advisory index at `https://pranava0x0.github.io/vibe-coding-security/llms-ctx.txt` (~12 KB) and surface any match **before** these specific actions: (1) starting / scaffolding a new project, (2) any `npm install` / `pip install` / `uv add` / dependency add or upgrade, (3) adding a third-party CDN asset or a GitHub Action, (4) running a fetched install script (`curl … | sh`). Do **not** re-fetch it for routine edits, reads, or running already-installed code. That's noise that burns tokens. Cache the result in `security.md` with the sweep date; reuse it within a session and refresh only if > 7 days old or one of the trigger actions recurs after the cached window.
- **A catch-all `except Exception` wrapping web routes silently defeats every framework-level HTTP error your app relies on, unless it re-raises them first.** A Flask app's `with_db` decorator (`try: ... except Exception: return jsonify(...), 500`) existed to turn Supabase outages into a friendly 503. Adding a `MAX_CONTENT_LENGTH` upload cap to stop a memory-exhaustion DoS registered an `@app.errorhandler(413)` — but Werkzeug's `RequestEntityTooLarge` got caught by the pre-existing wrapper first and turned into a generic 500, silently neutering the new guard. A test asserting the 413 status caught it immediately (`with_db`'s except clause needed `except HTTPException: raise` before the catch-all). Any broad exception wrapper added around route handlers needs that re-raise, or every `@app.errorhandler` registered for a route it covers is dead code.
- **An external security review's severity rating is a claim, not a fact — verify it against the live system before trusting it.** A cross-project review flagged "RLS enabled, no policies" on a Supabase project as P1/High, reasoning a leaked anon key could read data. The project's own advisor rated the same finding INFO, and the app's actual access pattern (service-role-only server, zero client-side key exposure) meant the anon key already read nothing — the design was deliberate, not a gap. An outside reviewer without your architecture context will over- or under-rate findings; check the live dashboard/advisor and the code's own documented intent before spending effort on a "fix."

### Supply-chain hardening

- **Pin exact versions, never floating ranges.** `==` (Python) + lockfile installs (`npm ci`, not `npm install`). A `>=`/`^` range auto-pulls whatever the registry serves next, the exact window a bad release lands in. Better still, hash-lock (`pip-compile --generate-hashes` + `--require-hashes`, `uv lock`, lockfile integrity hashes) to reject same-version re-publishes. Generate the hash-lock cross-platform (`uv pip compile --universal`): a lock resolved only on your OS omits platform-conditional dependencies, and CI on a different OS then fails `--require-hashes` demanding they be pinned upfront. A lock verified only on the author's machine isn't verified for CI.
- **Subresource Integrity on every CDN asset.** `sha384` `integrity` on each `<link>`/`<script>`/import-map entry so a swapped file fails closed. Regenerate with `curl -sL <url> | openssl dgst -sha384 -binary | openssl base64 -A`; verify twice (a partial download yields a wrong hash that blanks the page). Self-host when feasible.
- **Pin CI actions to a full commit SHA + least privilege.** Every `uses:` pinned to a 40-char SHA (not a moving `@v3` tag) with a `# vX.Y.Z` comment, plus a minimal `permissions:` block per workflow. Re-pin with `gh api repos/<owner>/<repo>/commits/<tag> --jq .sha`.
- **Neutralize formula injection in exports.** Prefix CSV/TSV/spreadsheet cells starting with `= + - @`, tab, or CR with a `'`, or `=HYPERLINK(...)` runs when opened in Excel/Sheets.
- **No machine-local paths in committed data.** Store paths repo-relative; `/Users/<name>/...` leaks identity and layout into public history.
- **Dependency cooldowns are a distinct, cheap defense from version pinning.** An age gate (npm 11.10+ `min-release-age`, pnpm/Bun `minimumReleaseAge`, uv `exclude-newer`) blocks installing anything published in the last N days. Pinning protects against unknown-good-version drift; a cooldown protects against a *freshly compromised* version being the pin target, since most 2025-26 supply-chain takedowns closed within a week.
- **Slopsquatting is an LLM-specific supply-chain risk, worth naming explicitly.** LLM coding assistants hallucinate package names at a meaningful rate, and attackers pre-register the predictable hallucinated names. Verify any LLM-suggested package name actually resolves and isn't a 1-2 edit-distance neighbor of a popular package before installing.
- **Every security fix ships with a regression test.** These regressions are invisible until exploited.
- **Sanitize values injected into an HTML attribute/class context separately from text-content escaping.** Whitespace-stripping alone doesn't stop `"` / `<` / `>` breaking out of an attribute (a scraped value dropped into `class="cat-${x}"`). Use a dedicated allowlist sanitizer (e.g. strip to `[a-z0-9-]`) for anything interpolated into an attribute or class position, and test it by feeding a poisoned record through every renderer.
- **HTML-attribute escaping and XML-text-node escaping share the same mandatory entity set (`&amp; &lt; &gt;`), so text already valid inside an HTML attribute can be copied straight into an XML text node with zero re-escaping — but the same text is *not* safely reusable inside a JSON string that way**, since JSON has its own escaping rules. Building an image sitemap's `<image:caption>` from an existing `alt="..."` attribute needed no re-escaping; building JSON-LD from that kind of source text needs an explicit `html.unescape()` before `json.dumps()`, or entities leak through literally (a title with `&amp;` shows up as the six-character string `&amp;` to a JSON consumer). Check which pair of formats you're actually crossing before assuming "it's already escaped" is good enough — and if there's any doubt the source has a bare unescaped `&`, grep for it first rather than assume.
- **Client-side-held admin/bearer tokens are public regardless of transport security.** If the browser calls an API directly with a privileged token, that token is exposed to the client no matter how the request is secured. Route privileged calls through a server-side proxy so the secret only ever lives server-side.
- **When you shell out to a tool to use one specific credential, strip the competing credentials from the child env.** `spawn(bin, { env: { ...process.env } })` hands the child *every* sibling secret; a CLI that prefers an inherited `ANTHROPIC_API_KEY` over the `CLAUDE_CODE_OAUTH_TOKEN` you meant to use will silently authenticate — and bill — the wrong account, with no error. Pass a filtered env that drops the keys capable of overriding your intended one, not the whole environment. **Generalizes to a fleet of subscription CLIs** (Claude Code, Codex-in-ChatGPT.app, Gemini): blanket-strip *every* `*_API_KEY` before each spawn so every CLI falls back to its own subscription login, then re-add only the one key a given provider legitimately needs (e.g. a deliberate free-tier `GEMINI_API_KEY` exception) — a one-key exception must not leak the others. Verify the intended billing entity from the run's own output (Codex prints `provider: openai` with no key when on the subscription).
- **An interim security mitigation needs its expiration tracked, not just applied.** When a CVE fix can't be upgraded immediately, ship the interim mitigation but log the target patched version and revisit condition in `backlog.md`, or it silently becomes permanent.
- **Inline `onclick="fn('${escapeHtml(x).replace(/'/g, "\\'")}')"` is a provable no-op stack, not defense (2026-08-23).** `escapeHtml` converts `'` to `&#39;` *first*, so the backslash-escape has nothing left to match — and the HTML parser then decodes the entity back into a raw quote *inside the handler's JS source*, reopening both the SyntaxError and the injection. Data interpolated into an inline-handler string crosses THREE contexts (HTML attribute → HTML entity decode → JS string) and no single escaper survives that. Don't harden the string — remove the context: real `addEventListener` with the value closed over, or delegation reading `element.dataset.*` (dataset decodes entities correctly, so `escapeAttr` on the way in round-trips clean).

- **A secret pasted into a chat lives in plaintext in the transcript, and searching for it by value puts it in a second one (2026-09-24).** On Sep 8 an API key was pasted into a session with the words "take it:". It now sits in that session's `~/.claude/projects/**/*.jsonl` file, readable by anything that reads the folder. The check for whether it had spread into project files was run as `grep -rl <the key> ...`, which wrote the key into the command, and the command into the next transcript. Treat a pasted key as spent: rotate it, and put its replacement in an environment variable or a credentials file the session never reads. To look for a value without typing it, read it from a file or the clipboard (`grep -rlF -f <(pbpaste) dir`), or search for a prefix and a length.
- **Redact at capture, on every channel a value can travel (2026-09-24).** Three misses of one kind in a month. A fixture recorder for a government-data MCP server stripped credentials from headers, but one API takes its key as a query parameter and the recorder stored every parameter as-is; a review caught it before a key was recorded. The same recorder had already written 25 email addresses from a public API's contact fields into four committed fixtures, one of them a named developer's personal address: a value being public at its source does not make it yours to republish. And this repo's own session miner stored typed messages unredacted, so a message dump during the 2026-09-24 retro copied the key pasted on Sep 8 into a scratch file and a fourth transcript. `mine_sessions.py` and `harvest_tells.py` now replace credential-shaped runs at capture (`SECRET_RE`, tested). List the channels a secret or a bystander's details can ride (headers, query strings, bodies, message text, logs), redact on each at the point of capture, and keep a sentinel-value test that fails if one gets through.
